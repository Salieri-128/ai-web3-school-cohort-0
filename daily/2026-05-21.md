## 今日笔记
今天我集中学习了 Handbook 里五个更偏工程化的主题：Vibe Coding、MCP、Evaluation、Fine-tuning 和 Inference。和前几天偏概念性的 LLM、Prompt、Context、RAG、Agent、Framework 相比，今天更像是在理解：**当 AI 真正进入开发流程和产品系统后，应该怎么安全、稳定、可控地落地。**

### 1. Vibe Coding：AI 不是替我写完代码，而是帮我缩短工程反馈循环
- Vibe Coding 不是“把需求扔给 AI 然后等代码出现”，而是人和 AI Coding Agent 协作开发。
- 人负责目标、边界、约束和验收；AI 负责搜索代码、生成 patch、修改文件、跑测试、解释错误。
- 它的核心不是自动写代码，而是缩短“看代码 → 改代码 → 跑测试 → 看反馈 → 再修改”的循环。
- 真正重要的不是“生成得快不快”，而是：任务是否足够小、上下文是否给得准、验证是否够硬。
- 这让我意识到，AI 写代码能力越强，人越要重视 repo、测试、diff、权限和提交边界，否则速度只会放大混乱。

### 2. MCP：标准化模型与外部工具/数据的连接方式
- MCP（Model Context Protocol）想解决的不是模型变聪明，而是模型如何以统一、可描述、可管理的方式访问外部能力。
- 可以把 MCP 理解成 AI 应用的“工具接口标准”：client 负责连接模型，server 负责暴露 resources、tools、prompts。
- MCP 的关键价值在于：工具可发现、调用有 schema、错误可传递、权限边界更清楚。
- 我今天最重要的理解是：模型不应该直接拥有世界，而应该通过明确协议访问被授权的上下文和工具。
- 但 MCP 只是连接协议，不等于安全本身；真正的授权、审计、隔离和副作用控制，仍然要靠外部系统设计。

### 3. Evaluation：把“感觉不错”变成“可以重复验证的改进”
- Evaluation 的作用是让 AI 系统的优化不再依赖主观感觉，而是依赖明确样本、指标和回归测试。
- 没有 eval，就无法判断 prompt、模型、RAG 或工具策略的变化，到底是真的更好了，还是只是碰巧在几个例子里看起来更顺。
- 我理解了几个关键组件：
  - **Harness**：负责运行评估流程
  - **Golden Set**：高质量测试样本集
  - **LLM-as-Judge**：用模型对开放式输出打分
  - **Regression**：防止“修了 A 又坏了 B”
  - **Observability**：观察线上真实行为和失败点
- 今天最大的收获是：AI 系统如果不能被重复测量，就很难被稳定改进。

### 4. Fine-tuning：微调是调行为分布，不是万能补丁
- Fine-tuning 不适合在模型效果一不好时就立刻上，它更适合提升格式稳定性、风格一致性、领域任务表现和工具调用习惯。
- 它不能替代 prompt、RAG、tool use、权限边界和实时知识获取。
- Handbook 让我很明确地意识到：微调前应该先问清楚，问题到底来自 prompt、context、retrieval、schema，还是模型本身。
- 我也理解了几个关键词：
  - **SFT**：监督微调，用输入/输出样本训练特定行为
  - **LoRA / PEFT**：用更低成本进行参数高效微调
  - **Dataset**：训练、验证、测试、回归集必须分开
  - **Overfitting**：如果数据少、风格单一或训练过度，模型会只会背例子，泛化能力变差
- 我今天的核心理解是：微调改变的是模型行为分布，不是产品系统边界；它不能把模型直接变成可信执行层。

### 5. Inference：模型上线后真正面对的是延迟、成本、稳定性和部署边界
- Inference 不是一个简单 API 按钮，而是模型如何在真实产品里被调用的问题。
- 需要综合考虑延迟、成本、质量、隐私、并发、监控、重试、降级和可替换性。
- 我理解了几个层次：
  - **API Model**：上手快，但要处理速率限制、超时、成本和版本回归
  - **Local Model**：可控性更高，但更依赖硬件、量化、推理框架和部署能力
  - **Quantization**：降低资源需求，但可能影响输出质量
  - **Serving**：关注并发、队列、流式输出、缓存、监控、健康检查和灰度发布
- 今天最重要的认识是：训练决定模型学到了什么，推理决定模型能否在真实系统中稳定交付可用结果。

### 今天形成的一条整体主线
如果把今天这五个主题串起来，我会这样理解：
- **Vibe Coding** 解决的是“人如何和 AI 协作开发软件”
- **MCP** 解决的是“模型如何标准化连接外部工具和上下文”
- **Evaluation** 解决的是“系统优化后如何判断是否真的更好”
- **Fine-tuning** 解决的是“模型行为如何在特定任务上变得更稳定”
- **Inference** 解决的是“模型如何在真实产品中被稳定、可控地调用”

这五个主题一起让我开始从“AI 会不会回答问题”转向“AI 系统如何被工程化组织、验证和部署”。
